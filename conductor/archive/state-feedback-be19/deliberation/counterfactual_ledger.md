# Counterfactual ledger — BEYOND-19

What each rejected or deferred path would have cost, and what would have brought it back. Every
entry names the observation that would falsify the decision, so this is a live ledger and not an
epitaph.

| # | Path not taken | Why not (measured, not assumed) | What would bring it back |
|---|---|---|---|
| 1 | **Per-control spinners** (`candidate_b_per_control_spinners.md`) | Seven lifetimes, seven print-hide entries, seven shapes to keep on-theme — and the class returns at the next operation the extension grows. The `.be-ai-busy` node is itself the evidence: one flow grew a private marker because there was no shared one. | **Recall condition:** an operator/design ruling that the affordance must sit INSIDE the control's own box (a spinner replacing the Print row's label). Then B's spatial honesty beats A's maintenance argument and the geometry changes. |
| 2 | **AC-7: an assembly marker around `applyLayout`** | **DEFERRED, not rejected.** A rebuild is synchronous inside the content script: raise → rebuild → clear all happen in one task, so the browser never paints the marker. A marker that never paints is worse than none — it looks like a fix in the diff and does nothing on screen. | The real fix is an event-loop yield (`await new Promise(r => requestAnimationFrame(r))`, or a microtask boundary) between teardown and re-render inside `js/layout_apply.js`. That path is used by every drag, every undo, every restore — landing it needs the full e2e corpus run against it, which is a track of its own. |
| 3 | **Re-implementing AC-5/AC-6 feedback** | Audited first and found ALREADY PRESENT: `js/ai_settings.js` has distinct success/error copy (`aiSaveErrorMessage`, 5 call sites) and `js/controls.js`/`js/dnd.js` already toast "Shape added" / "Layout saved". The judge's bundles simply never sampled a save. Writing a second surface for an existing one would have been pure churn and a drift risk. | A future certification that actually SAMPLES the settings save and still reports no feedback — that would mean the existing copy is not reaching the user, which is a different defect from "it does not exist". |
| 4 | **A second e2e spec for AI borders (AC-2)** | Both capabilities ride `arrangeWithAi` → `sendByokChat`; the marker wraps the transport, so a marker defect breaks both and the AC-1 spec sees it. A border-specific spec would assert the same node from the same seam. | A future change that gives borders a DIFFERENT transport or a different marker. Then the shared coverage stops being true and a dedicated spec is owed. |
| 5 | **`waitForFunction` as the observation primitive** | MEASURED, not assumed: in this Playwright build it returns a `JSHandle`, and serialising it back through CDP produced `RangeError: Array buffer allocation failed` — twice, on different code paths. | A Playwright upgrade where `waitForFunction` resolves to a boolean in this configuration. The main-world poll loop is the workaround and it is also what the rest of this repo's specs do. |
| 6 | **Diagnosing the red phase as "the marker isn't painted"** | FALSIFIED by measurement: a main-world `querySelectorAll(".be-ai-busy").length` poll returned **1** while the fetch was in flight. The marker was always painted; the harness could not observe it because the only probe action (`start`) awaits the flow and samples AFTER `clearBusy`. | Nothing — this was simply wrong, and it is recorded so the next session does not re-derive it. The fix (a new `async_start` probe action) is what made the red → green transition observable at all. |
| 7 | **Hiding `.be-ai-busy` in only one print list** | Both lists exist (`js/ui_theme.js`'s theme block and `js/print_styles.js`'s injected boot stylesheet). The theme block hid `.be-activation-overlay` and friends but neither marker class; the boot block hid `.be-feedback` and friends but neither marker class. `.be-ai-busy` was in **NEITHER** — a real pre-existing leak. | Nothing. Both classes are now in both lists, and the contract test reads the INJECTED stylesheet (not source text), so a rule that stops being injected fails immediately. |

## The one thing this ledger refuses to do

It does not re-label AC-7 as "out of scope". The finding is real, it is the judge's f12, and it
is still open on the product — the ledger entry exists so the next session starts from the
diagnosis (synchronous rebuild, needs a yield) instead of re-discovering it.
